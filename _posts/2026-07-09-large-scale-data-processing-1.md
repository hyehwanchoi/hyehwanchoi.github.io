대량의 데이터를 다루는 시스템에서 데이터를 제때 전달하는 것은 처리 속도만큼 중요합니다. 일정 주기로 데이터를 모아 처리하던 흐름을 실시간으로 전환하며, 문제를 확인하고 성능을 검증한 과정을 정리했습니다.

## 왜 처리 흐름을 바꿨을까

기존에는 데이터를 일정 주기로 수집하고 가공한 뒤 후속 모듈로 전달했습니다. 이 방식에서는 사용자가 최신 정보가 필요한 상황에서도 이전 시점의 데이터를 확인할 수밖에 없었습니다.

저는 데이터 수집부터 가공, 전달까지의 흐름을 검토하고, 메시지를 받은 뒤 실시간으로 처리해 전달하도록 변경했습니다. 기존 모듈 간 연동은 유지하면서 처리 시점을 개선하는 데 집중했습니다.

## 전체 흐름을 기준으로 성능 확인하기

실시간 전환은 데이터를 빨리 읽는 것만으로 끝나지 않습니다. 후속 모듈에 전달하고 응답을 받는 과정까지 확인해야 전체 흐름의 지연을 파악할 수 있습니다.

Kafka 클러스터를 활용하는 환경에서 로그와 Kafka UI를 구축하고 부하 테스트를 진행했습니다. 데이터 수신과 전달 과정, 후속 모듈의 응답 시간을 함께 확인하며 처리 흐름을 검증했습니다.

## 지연을 확인하고 다시 검증하기

후속 모듈의 응답이 늦어지는 경우에는 처리 흐름을 점검하고 데이터 전달량을 조정할 수 있는 옵션을 적용해 다시 확인했습니다. 그래도 지연이 이어지면 해당 모듈 담당자에게 확인을 요청하고 함께 성능 테스트를 진행했습니다.

이번 개선에서는 특정 구간의 속도만 보는 것보다, 데이터가 들어와 결과가 전달될 때까지 전체 흐름을 관찰하고 반복해서 검증하는 것이 중요했습니다.
